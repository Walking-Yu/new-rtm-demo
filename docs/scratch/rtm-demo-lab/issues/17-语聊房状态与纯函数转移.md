### 迁移等价性已验证

同一份测试在两个位置各跑一次，结果完全一致（各 6/6 通过）：

```
npx vitest run src/scenes/voice-room/transitions.test.ts            # 新位置 6 passed
npm --prefix demos/voice-room test -- src/domain/transitions.test.ts # 遗留位置 6 passed
```

这就是本票要的「有意义的 RED → 搬实现 → 行为契约不变」闭环。

### 更正搬迁前的几处误判

开工时我读的是根 `src/legacy/` 的旧版本，据此报出「遗留测试 44 个用例、17 个转移函数、`transitions.ts` 依赖 `protocol.ts` 需内联两个判定函数」。核对 `demos/voice-room/` 现行版本后更正为：**6 个用例、15 个转移函数、完全不依赖 `protocol.ts`**。因此没有引入任何不必要的内联，搬迁是干净的移动。

### 状态适配器：三个纯函数

`parseStored` 按本票要求**不沿用遗留的「无效返回 fallback」**：无效输入返回 `undefined`，兜底策略交给调用方。它校验 `revision` 为数、`seats` 为对象而非数组、`queue` 与 `bannedUserIds` 为数组，缺字段或类型不符一律返回空值，且**不抛异常**——无效数据是常态而非异常。

`reduce` 是判别式联合动作到转移函数的分发。领域错误照常抛出，`reduce` 不吞规则违规——权限与状态机规则仍然只住在 `transitions.ts` 里，RTM 文件只知道「调 reduce 得到下一个快照」。

### 麦位激活仍由媒体结果驱动

`seat.activate` 与 `seat.rollback` 都走 `reduce`，测试覆盖 `joining → active` 与失败回滚两条路径。这个顺序 UI 与 E2E 都依赖，没有改动。

### 端数不进注册表

`config.ts` 承载 `SEAT_COUNT` 与 `MAX_CLIENTS`，注册表仍然只有四个字段。另加一条护栏测试断言 `SEAT_COUNT` 与 `createInitialSnapshot` 实际生成的麦位数一致——这两处目前是同一个数字的两份，护栏防止它们漂移。
