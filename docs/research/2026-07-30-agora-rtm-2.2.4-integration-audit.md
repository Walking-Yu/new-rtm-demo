# Agora RTM Web 2.2.4 integration audit

> Historical baseline: after this audit was completed, the active demo dependency was switched to a locally provided `2.3.0` package (now vendored at `vendor/agora-rtm-2.3.0/`). This report preserves the 2.2.4 findings for comparison; it does not describe the currently installed SDK version.

Date: 2026-07-30  
Scope: `demos/voice-room`, Web, `agora-rtm@2.2.4`  
Conclusion: **confirmed**, with the version caveats below.

## Evidence boundary

The version-locked source of truth is the installed `agora-rtm@2.2.4` package:

- [`package.json`](../../demos/voice-room/node_modules/agora-rtm/package.json) identifies version 2.2.4 and an exact `agora-rtc-sdk-ng@4.23.0` peer dependency.
- [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts) defines the public 2.2.4 API.
- [`agora-rtm.js`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.js) is the shipped implementation (`v2.2.4-0-gfd60c918`).
- The local knowledge base's [2.2.4 release note](../../../rtm-board/web-rtm-knowledge/content/releases/web-rtm-2.2.4.md) confirms the tag and reconnect/metadata/Lock fixes. Its architecture and capability-map stable pages are scoped to **2.3.x**, so they are only routing context and are not used to assert 2.2.4 behavior.
- The official API pages are current, not version-pinned. Where they differ from the installed package, this audit follows the installed 2.2.4 declaration and bundle.

## Findings

### P0 (resolved in current patch): The room state Lock was acquired before it had ever been created

`RoomStateRepository.mutate()` calls `acquireLock("room-state")`. In the audited baseline, neither the repository nor the adapter called `setLock`. The official sequence is `setLock` then `acquireLock`; error `-14008` is `RTM_ERROR_LOCK_NOT_EXIST`. The shipped implementation sends a lock-acquire request and does not implicitly create the Lock. Therefore the first host state mutation during connection could fail after RTC had already joined and published the microphone.

The current patch now handles `-14008`, creates the Lock, tolerates the `-14004` concurrent-creation race, and retries acquisition once. The focused adapter suite covers both paths and passes.

Evidence:

- App call site: [`RoomStateRepository.ts`](../../demos/voice-room/src/runtime/RoomStateRepository.ts#L43) and [`AgoraRtmAdapter.ts`](../../demos/voice-room/src/runtime/agora/AgoraRtmAdapter.ts#L137).
- Public signatures and retry definition: [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L603).
- Official [Lock API](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-lock/lock#acquirelock) and [error codes](https://doc.shengwang.cn/doc/rtm2/javascript/error-codes).
- Shipped implementation: `LockImpl.setLock`, `LockImpl.acquireLock`, and `_requestAcquireLock` in [`agora-rtm.js`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.js).
- The repository test still uses a memory success path, while the adapter contract tests now cover missing and concurrently created Locks: [`RoomStateRepository.test.ts`](../../demos/voice-room/src/runtime/RoomStateRepository.test.ts#L60) and [`AgoraRtmAdapter.test.ts`](../../demos/voice-room/src/runtime/agora/AgoraRtmAdapter.test.ts#L109).

Exact change:

1. Add a `setLock(channelId, "MESSAGE", lockName)` capability, or lazily initialize in `AgoraRtmAdapter.acquireLock` when acquire returns `-14008`.
2. For lazy initialization, tolerate `-14004 RTM_ERROR_LOCK_ALREADY_EXIST` because two clients can race to create the same Lock, then retry acquire once.
3. Keep `{ retry: false }` and add a bounded application retry with jitter for `-14007 RTM_ERROR_LOCK_ACQUIRE_FAILED`. Do not blindly switch to `{ retry: true }`: the public contract waits until acquisition succeeds or the client exits the channel, so a UI command can remain pending without an application timeout.
4. Detect structured SDK errors using `errorCode`/`code`, with the symbolic reason as a fallback, before converting the error to a generic `Error`.

### P1 (resolved in current patch): Presence returned only the first page

The audited baseline mapped only the first response and ignored `nextPage`. Version 2.2.4 returns a bookmark and requires it as `options.page` on the next call. The declared/default page size is 50, so larger rooms would silently show a partial online list. It also requested state that it discarded. The current patch loops over every page, deduplicates IDs, and uses `includedState: false`; the two-page contract test passes.

Evidence:

- App implementation: [`AgoraRtmAdapter.ts`](../../demos/voice-room/src/runtime/agora/AgoraRtmAdapter.ts#L101).
- Pagination contract: [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L703).
- Official [Presence `whoNow`](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-presence/presence#whonow) documents `page` and `nextPage`.

Exact change: loop until `nextPage === ""`, pass the previous `nextPage` as `page`, set `includedState: false`, and deduplicate user IDs defensively across pages. Add a two-page adapter test.

### P1 (core issue resolved, event detail pending): Deprecated and current connection events were both authoritative

The audited baseline registered both `status` and `linkState`. The official configuration page marks `status` deprecated, while 2.2.4 emits both for the same connection lifecycle. The current patch now uses only `linkState` and correctly maps the tested automatic reconnect sequence. It still reduces the structured event to `(state, reasonCode)`, so `serviceType`, `operation`, `isResumed`, and channel restoration context remain unavailable to the orchestration layer.

Evidence:

- App listeners: [`AgoraRtmAdapter.ts`](../../demos/voice-room/src/runtime/agora/AgoraRtmAdapter.ts#L164).
- Event map and `LinkStateEvent`: [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L1377).
- Official [configuration/event page](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-configuration/configuration) explicitly labels `status` deprecated.
- The shipped `RTMImpl` emits both `status` and `linkState`: [`agora-rtm.js`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.js).

Exact change: use `linkState` as the sole Message service connection signal. Map `SUSPENDED`, and `DISCONNECTED`/`CONNECTING` with `operation === "AUTO_RECONNECT"`, to the app's `reconnecting` state; map terminal `FAILED` separately. Preserve `serviceType`, `operation`, `reasonCode`, `isResumed`, `affectedChannels`, and `unrestoredChannels` in the port event instead of reducing the event to two strings.

Version caveat: although the 2.2.4 public type exposes `unrestoredChannels`, the shipped Message implementation constructs it as an empty array. Do not use that field as the only restoration decision on 2.2.4.

### P1 (duplication resolved, revocation handling pending): Token expiration was delivered twice

The audited baseline listened to both `tokenPrivilegeWillExpire` and `token`, and invoked `tokenExpiring()` for every `token` event. In the shipped 2.2.4 implementation, one expiring token emits **both** event names. The current patch now listens only to `token` and filters `WILL_EXPIRE`, so duplicate and false expiration reports are fixed. `READ_PERMISSION_REVOKED` is currently ignored rather than surfaced to the app.

Evidence:

- App listeners: [`AgoraRtmAdapter.ts`](../../demos/voice-room/src/runtime/agora/AgoraRtmAdapter.ts#L199).
- `TokenEventType` and event map: [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L364) and [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L1391).
- Shipped `_tokenPrivilegeWillExpireHandler` emits `tokenPrivilegeWillExpire` followed by `token/WILL_EXPIRE`; `renewToken` and permission handling emit `token/READ_PERMISSION_REVOKED`: [`agora-rtm.js`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.js).
- The official configuration page omits `token` from its event table, which conflicts with the exported 2.2.4 API and shipped runtime; this is a documentation gap.

Exact change: subscribe only to the versioned `token` event, call `tokenExpiring()` only for `eventType === "WILL_EXPIRE"`, and expose a distinct permission-revoked handler carrying `affectedResources.messageChannels`. A production token flow must call `renewToken`; merely displaying an error does not keep an authenticated session alive.

### P1 (resolved in current patch): A partially failed connect was not unwound

The audited baseline could fail after RTM login/subscription and RTC join while only changing UI state. `AgoraRtmAdapter.connect()` also dropped a client whose login rejected without a best-effort `logout()`. A retry could therefore start over while earlier resources were still active.

The current patch tracks successful RTM login, Message Channel subscription, and RTC join stages. A later failure now unwinds only completed stages in reverse order (`rtc.leave`, `rtm.unsubscribe`, `rtm.disconnect/logout`). Cleanup failures do not mask the original connection error. A rejected adapter login also attempts `logout()` before releasing its client reference and preserves the mapped login error.

Evidence:

- Orchestration: [`VoiceRoomClient.ts`](../../demos/voice-room/src/runtime/VoiceRoomClient.ts#L125).
- Adapter login failure path and logout: [`AgoraRtmAdapter.ts`](../../demos/voice-room/src/runtime/agora/AgoraRtmAdapter.ts#L53).
- In 2.2.4, `logout()` is the public lifecycle cleanup API; there is no public `dispose()` method: [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L2046).
- Official [`login`/`logout`](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-configuration/configuration#login) contract.

Implemented behavior: track completed stages and unwind them in reverse order on failure. On a rejected adapter login, call `logout()` best-effort before releasing the instance and never mask the original login error. Normal shutdown remains unsubscribe followed by logout; no extra `dispose()` call exists in this SDK version.

### P2: The RTC dependency is currently compatible but not reproducible

The installed tree resolves `agora-rtc-sdk-ng@4.23.0`, exactly matching the 2.2.4 package peer dependency. However, the demo manifest says `"latest"`, so a future clean install can pull an incompatible version. The current official configuration page still demonstrates 4.22.0, which is stale for this package version.

Evidence:

- Demo manifest: [`package.json`](../../demos/voice-room/package.json#L13).
- Installed RTM peer declaration: [`agora-rtm/package.json`](../../demos/voice-room/node_modules/agora-rtm/package.json).
- `npm ls` at audit time: RTM 2.2.4 and RTC 4.23.0.
- Official [initial configuration](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-configuration/configuration) currently shows 4.22.0.

Exact change: pin `agora-rtc-sdk-ng` to `4.23.0` while RTM remains 2.2.4, and upgrade the pair intentionally after validating the new RTM peer range.

## Correctly integrated behavior

- **Constructor:** `new AgoraRTM.RTM(appId, userId, { logLevel: "warn", useStringUserId: true })` matches `RTMConfig`. String IDs are appropriate because the app uses string RTC UIDs. See the [constructor/config API](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-configuration/configuration) and [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L1812).
- **Tokenless login:** `login({ token: undefined })` is valid when project Token authentication is disabled. `LoginOptions.token` is optional, and the official page allows omitting it. If App Certificate/Token authentication is enabled, omission must fail. See [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L1911) and the official [`login`](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-configuration/configuration#login) section.
- **Listener timing:** registering events before `login()` is correct and avoids missing early lifecycle events.
- **Subscription options:** explicitly enabling Message, Presence, Channel Metadata, and Lock events matches this room's feature set. `beQuiet` correctly remains false/default so both endpoints are visible in Presence. See the official [`subscribe`](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-channel/channel#subscribe) contract and [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L1698).
- **Publish routing:** omitting `channelType` for Message Channel and setting `{ channelType: "USER" }` for direct messages is correct. A publisher need not subscribe before publishing. See the official [`publish`](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-message/message#publish) examples and [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L1937).
- **Storage CAS:** reading `majorRevision`, then writing with that `majorRevision` and the held `lockName`, is the right global snapshot CAS. Setting item `revision: -1` deliberately leaves item-level CAS off while global CAS remains on. See the official [`setChannelMetadata`](https://doc-internal.shengwang.cn/doc-new/rtmjs/api-ref/rtm2/javascript/toc-storage/storage#setchannelmetadata) contract and [`agora-rtm.d.ts`](../../demos/voice-room/node_modules/agora-rtm/agora-rtm.d.ts#L920).
- **Reconnect state recovery:** the app already re-subscribes and reloads Presence plus the Storage snapshot after reconnect. That explicit event-plus-snapshot recovery is appropriate for 2.2.4, whose runtime does not provide useful `unrestoredChannels` contents. Keep the reload; make it trigger exactly once from `linkState`.

## Focused regression tests

The focused adapter suite passed 8/8 after the current patch. Covered items include tokenless login, rejected-login cleanup, one connection event source, token-event filtering, Presence pagination, missing Lock creation, concurrent Lock creation, and core Message/Storage/Lock routing. The orchestration suite also covers RTM hydration rollback and reverse-order RTC/RTM cleanup without error masking.

Still required:

1. `linkState` drives exactly one end-to-end hydration, including a reconnect where resubscribe or snapshot reload fails.
2. `token/READ_PERMISSION_REVOKED` reaches a distinct application handler.
3. Lock contention (`-14007`), bounded retry, and release in `finally`.
4. Metadata `majorRevision` conflict and lock ownership failure.
