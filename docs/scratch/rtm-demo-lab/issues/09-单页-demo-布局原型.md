# 单页 demo 布局原型

Type: prototype
Status: resolved
Blocked by: 05

## Question

单个 demo 页面的布局长什么样？做一个粗糙可看的原型来对齐，而不是继续在文字上讨论。

参考：`docs/inputs/单个demo页面的参考UI.png`（腾讯云音视频）——顶部一级 tab 带左右滚动箭头，下方二级 tab 横排，中间 main container 放演示，右侧信息栏。本项目把右侧换成 API/事件时间线面板。

需要通过原型回答：

- 两级 tab 的滚动交互（箭头、滚轮、键盘）与当前项高亮。
- main container 与时间线面板的宽度比例；时间线在窄屏怎么处理。
- 时间线条目的视觉形态：api 节点与 event 节点如何区分，uid 前缀怎么展示，多端如何并列或交错。
- 场景说明文字、能力标签（Presence/Storage/Lock 等）放在哪。
- "建设中"场景的占位形态。

被 `05` 阻塞：时间线的数据字段定了才知道每个节点要显示什么。

## Answer

原型已建（`demos/voice-room/src/prototype/`，约 1500 行，全假数据、不连 RTM/RTC），经用户两轮修改后确认。**原型是一次性的，确认后删除**，以下是从它提取出的、必须进 spec 的布局决策。

### 整页骨架

自上而下四层，每层职责固定：

```
横幅（仅原型有，正式版去掉）
一级 tab 条（左 logo，中间 8 个分类，右侧 env 提示）
二级 tab 条（药丸形，当前一级分类下的场景）
主体 = 主区（minmax(0, 1fr)） + 时间线面板（400px）
```

- 主区与时间线宽度比例 **`1fr / 400px`**，时间线固定宽、主区吃剩余空间。
- 时间线可折叠成 **40px 竖条**（竖排标题 + 条目计数），点击展开。折叠态主体变 `1fr / 40px`。
- **≤1240px 断点**：网格退化为单列，时间线从右侧栏变为主区下方的横排区块。
- 切换场景只替换主区内容，一级/二级 tab 与时间线面板位置不动。

### 主区：两台手机并排

语聊房主区放**两台手机外框**（房主视角 / 听众视角），每台上方一个身份条：彩色 uid badge + 「房主视角 · Ava」。这是「一个标签页两个真实客户端」的可视化，与现有 `RoomPage` 的双端模型一致。

手机内部高度约束（用户明确修过两轮，不要回退）：

- 手机高度 `min(812px, calc(100vh - 210px))`，保证在常见笔记本屏上不裁切。
- 内部只有**公屏区域滚动**，其余区块 `flex-shrink: 0` 钉住。
- **底部输入条常驻手机框内**，不随公屏滚动。
- 麦位方框已按用户要求缩小两轮：`min-height: 76px`、头像 26px。麦位 4 列网格。

手机内区块顺序：状态栏 → 房间头部（标题/主题 + 模式/在线数/rev 三个 chip）→ 麦位网格 → 角色专属面板（房主看审批列表，听众看自己的申请状态）→ 成员条（横向滚动，超出显示 `+N`）→ 公屏 → 底部操作条（两端按钮不同）。

### 时间线条目形态

单列、按 `at` 归并**交错**呈现，**不按端并列分栏**。理由：本 demo 要展示的是「一个动作在两端引发的因果链」，分栏会把因果拆散。

行布局为三列网格 `16px 62px 1fr`：色点轨道 / 时间（`mm:ss.mmm`，砍掉小时）/ 正文。正文首行是 uid badge + 方法名或事件名，次行是 `detail` 摘要。

- **api 与 event 靠左侧色点区分**，面板顶部给图例（「RTM API 调用」/「RTM 事件」）。
- **uid 前缀用彩色 badge 前置**，颜色按 role 固定，与手机身份条上的 badge 同色，肉眼可对上是哪一端。

### 「建设中」场景的占位形态

未实现场景的二级 tab **可见可点**（与 `01` 一致），点进去主区是统一的占位说明页，右侧时间线面板保持存在。不给每个未实现场景单独写占位文案。

### 用户对三个待定问题的答复

**1. 两级 tab 滚动交互 —— 保持现状。** 原生横向滚动 + 隐藏滚动条，**不加**参考 UI 上的左右箭头，**不加**键盘导航。参考 UI 在这一点上不照抄。

**2. 场景说明文字与能力标签 —— 本阶段不做。** 后续若要写，位置定在**页面底部的一个可折叠 div**里，不占主区、不进手机、不放侧栏。骨架里可以留出这个位置，但不实现内容。（与 `01` 的「`capabilities` 不进注册表、归档到 `docs/`」不冲突：UI 上本就不显示。）

**3. 时间线筛选与截断 —— 要筛选，不要截断提示。**

- **不显示**「已截断」之类的提示。超出阈值直接丢弃最旧条目，静默进行。沿用 `05` 定的单实例环形上限 500 条。
- **需要筛选**，三个维度：
  - **uid**（哪个客户端实例）
  - **role**（host / audience）
  - **kind**（api / event）
- 三个维度对应 `TraceEntry` 上已有的 `uid` / `role` / `kind` 字段（见 `05`），不需要为筛选新增数据字段。
- 筛选是**纯 UI 层过滤**，不影响 trace 采集，也不影响环形缓冲的丢弃逻辑 —— 被筛掉的条目仍在 store 里，取消筛选即恢复。
- 面板已有的「清空」与「折叠」保留。

### 留给 charting 的实现要点

- 时间线面板归 `shared/timeline/`（见 `10` 的骨架形态），筛选状态是面板自己的 local state。
- 多实例归并 + `useSyncExternalStore` 订阅两份 `TraceStore`（`rtm-host.ts` / `rtm-audience.ts`），归并规则见 `05`：主排序键 `at`，同毫秒用实例内 `seq`。
- 原型的 CSS（912 行）不直接搬，但上面列出的具体数值（`400px`、`40px`、`1240px`、`min(812px, 100vh - 210px)`、麦位 `76px`、头像 `26px`、时间线三列网格）是用户确认过的，正式实现要沿用。
