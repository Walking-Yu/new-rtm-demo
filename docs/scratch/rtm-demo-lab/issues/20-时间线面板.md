# 20 — 时间线面板

**Blocked by:** 15, 16

**Status:** ready-for-agent

**What to build:** 右侧那条把 RTM API 调用与 RTM 事件串起来的时间线面板。单列按时间**交错**呈现两端的条目，**不按端并列分栏**——本 demo 要展示的是「一个动作在两端引发的因果链」，分栏会把因果拆散。

- [ ] API 调用与事件两类条目有不同的视觉标记，面板顶部给图例
- [ ] 每条前置彩色 uid badge，同角色同色，且与主区身份条上的 badge 同色
- [ ] 时间显示砍掉小时，只到分秒毫秒
- [ ] 支持按条目类型、角色、uid 三维筛选，三者都是条目上已有字段，**不为筛选新增数据字段**
- [ ] 取消筛选后条目恢复——要真断言这条，它证明筛选是纯 UI 过滤、没动 store，被筛掉的条目仍在里面
- [ ] 筛选状态是面板自己的局部状态，不影响 trace 采集、不影响环形缓冲的丢弃逻辑
- [ ] 「清空」与「折叠」按钮存在且可用
- [ ] 没有任何「已截断」提示
- [ ] 行布局照抄 spec 的三列网格数值
- [ ] 用外部 store 订阅机制接入 trace，不轮询

时间线**只呈现 RTM**，RTC 辅助模块不采集 trace——混入 RTC 节点会稀释「RTM 数据流」这条主线。RTC 的成败会体现为后续那次 RTM 调用的出现或缺席，因果仍然看得懂。若实测发现看不懂中间发生了什么，再考虑加一类媒体节点（已记入 spec 的未决项）。
