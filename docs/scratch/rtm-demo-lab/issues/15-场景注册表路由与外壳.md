### 23 个场景的来源

遗留 24 个减去两个语聊房场景（`voice-room-interaction` 礼物弹幕 + `voice-room-seats` 上下麦），合并成唯一一个 `ready` 场景 `voice-room`。

三个遗留 id 带一级分类前缀，按本票要求改名：`education-device` → `learning-device`、`enterprise-collaboration` → `team-collaboration`、`gaming-voice-social` → `game-voice-chat`。另有三个 `social-` 前缀的同样去掉：`social-presence` → `presence`、`social-chat` → `im-chat`、`live-social-pk` → `live-pk`。

### 四字段护栏是运行时断言

`Object.keys(scene).sort()` 逐个场景比对白名单，不是只靠类型。遗留的 `canvas` / `actions` / `initialStatus` / `supportsRealRtm` 被顺手加回来时测试会红。

`roles` 与 `capabilities` **不进注册表但不丢弃**：能力标签进 `capabilities.ts` 按 id 旁挂（占位页要显示"计划演示哪些 RTM 能力"），角色清单归档进 `场景实现资料.md`。

### 路由表与 router 分离

导出 `LabRoutes`（无 router）+ `App`（`BrowserRouter` 包壳）。测试用 `MemoryRouter` 指定起始路径，生产代码用 `BrowserRouter` —— 不必在生产代码里为测试留 router 分支。

### 结构保证而非约定保证

三处刻意用结构而不是约定来保证行为，测试直接断言结构：

- **切换场景只替换主区** —— layout route + `<Outlet />`。测试断言两级 tab 与时间线面板的 DOM 节点引用在切换前后 `toBe` 相同，不是"看起来还在"。
- **env 未配置不进场景** —— 判定在 `<Routes>` 之前 `return <EnvGuide />`，场景路由根本不存在，不是"渲染了但藏起来"。
- **已实现场景的主区** —— `sceneComponents` 是 `Map<string, ComponentType>`，配一条双向护栏测试：每个映射项必须是 `ready`，每个 `ready` 场景必须有映射。

第三条是 code review 找出来的：原先写成"非 planned 就渲染语聊房"，将来加第二个 ready 场景时会静默渲染成语聊房而不报错。

### code review 修掉的问题

- **`categoryId` 完全不校验** —— `/gaming/voice-room` 会渲染语聊房且二级 tab 无 active 项，"一级/二级"的从属关系形同虚设。现在校验分类确实包含该场景，错配走未找到页。
- **CSS 类名对不齐** —— `EnvGuide` 用 `__section`/`__subtitle`/`__code`，样式表里定义的却是 `__step-title`/`__note`，引导页实际没有样式。已改样式表匹配组件。
- **env 提示是硬编码** —— 顶栏写死"App ID 来自环境注入"，与真实配置无关。现在下传 `env.source`，显示真实来源（`window.__ENV__` 或 `import.meta.env`）。
- **缺 `shortLabel`** —— 票 01 要求窄屏短标签。现在 `label` 取回遗留的完整名（"社交 / 娱乐"），`shortLabel` 是短名（"社交"），两个 span 由 CSS 断点切换，`aria-label` 固定为完整 label 以免可访问名变成两者拼接。
- **窄屏只做到单列堆叠** —— 票要求"退化为主区下方的**横排**区块"。已补横向滚动的横排形态。
