# 24 — 交付物与开源合规

**Blocked by:** 13, 22

**Status:** ready-for-agent

**What to build:** 一个可以对外开源、任意机器可跑的仓库：许可证、README、环境变量样例齐全，无机器专属路径、无凭证入库，且 README 显式声明三件必须让客户知道的事。

- [ ] 环境变量样例文件留空并附注释说明去哪拿 appId
- [ ] 入口页加开发用内联脚本注入体验 appId，并注释说明「生产环境由上层页面注入，这段仅本地开发用」
- [ ] 许可证用 MIT，README 说明 vendor 下的 SDK 包版权归声网、遵循其自带许可证
- [ ] **README 三条必须声明，缺一不可**：多 RTM 实例是实测可行、官方文档未保证（附来源链接）；治理动作不构成信任边界、生产必须服务端校验；默认 appId 无 token 鉴权仅供体验、接入生产必须换成支持 token 的 appId
- [ ] README 另需一节说明「为什么 RTM 一角色一份而 RTC 共享一份」。**这节不能省**——少了它，后来者一定会尝试抽共享的 RTM 基类
- [ ] README 其余内容：快速开始、注入契约（国内站与国际站各一份脚本示例）、目录导览、「哪些文件可以直接拷走」
- [ ] 清掉仓库内所有机器专属绝对路径，项目说明文件里对 beta 包路径的历史描述改成 vendor 相对路径
- [ ] 确认无凭证入库：不含 App Certificate、不含 token 生成器、不预置任何密钥，本地环境变量文件本身不入库
- [ ] 全量验证：构建、单测、E2E 三项全绿
- [ ] 跨机器可安装性自检：删掉依赖目录重装能成功，且过程中不访问任何机器专属路径。这是「任意机器可跑」的最低验证，真正的验证要在另一台机器上做

**待 RTM SDK 正式发布到 npm 后**：把 vendor 相对路径依赖改回版本号引用并删除 vendor 目录。
