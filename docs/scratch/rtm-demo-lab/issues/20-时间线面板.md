# 20 — 时间线面板

**Blocked by:** 15, 16

**Status:** resolved

**What to build:** 右侧那条把 RTM API 调用与 RTM 事件串起来的时间线面板。单列按时间**交错**呈现两端的条目，**不按端并列分栏**——本 demo 要展示的是「一个动作在两端引发的因果链」，分栏会把因果拆散。

- [x] API 调用与事件两类条目有不同的视觉标记，面板顶部给图例
- [x] 每条前置彩色 uid badge，同角色同色，且与主区身份条上的 badge 同色
- [x] 时间显示砍掉小时，只到分秒毫秒
- [x] 支持按条目类型、角色、uid 三维筛选，三者都是条目上已有字段，**不为筛选新增数据字段**
- [x] 取消筛选后条目恢复——要真断言这条，它证明筛选是纯 UI 过滤、没动 store，被筛掉的条目仍在里面
- [x] 筛选状态是面板自己的局部状态，不影响 trace 采集、不影响环形缓冲的丢弃逻辑
- [x] 「清空」与「折叠」按钮存在且可用
- [x] 没有任何「已截断」提示
- [x] 行布局照抄 spec 的三列网格数值
- [x] 用外部 store 订阅机制接入 trace，不轮询

时间线**只呈现 RTM**，RTC 辅助模块不采集 trace——混入 RTC 节点会稀释「RTM 数据流」这条主线。RTC 的成败会体现为后续那次 RTM 调用的出现或缺席，因果仍然看得懂。若实测发现看不懂中间发生了什么，再考虑加一类媒体节点（已记入 spec 的未决项）。

## Answer

面板落在 `src/shared/timeline/`，五个模块加一个组件，全部由 `TimelinePanel.test.tsx` 的 39 个用例覆盖（连同票 16 的 `traceStore` / `mergeTraces` 共 63 个）。

**文件与职责**

| 文件 | 职责 |
| --- | --- |
| `TimelinePanel.tsx` | 面板本体：图例、三维筛选器、条目列表、清空/折叠 |
| `useMergedTraces.ts` | `useSyncExternalStore` 接入多端 trace，含引用记忆化 |
| `filterTraces.ts` | 纯函数三维筛选 + 选项收集 |
| `roleColors.ts` | 角色 → badge 配色的**唯一来源** |
| `formatTraceTime.ts` | `MM:SS.mmm` |

**逐条对照**

- **两类视觉标记 + 图例** —— 每行一个 `.lab-trace__dot`，`data-kind` 取 `api`/`event`，CSS 里 api 是实心靛蓝圆、event 是空心绿圈。图例复用**同一个类名** `.lab-trace__dot`，所以图例与条目的标记不可能对不上；图例在零条目时也渲染（读者先看懂标记再看数据）。测试：`面板顶部给出两类的图例，且色点样式与条目里的同一个类名`、`图例在没有任何条目时也在`。
- **badge 同色** —— 颜色全部走 `roleColor(role)`，面板源码里**没有任何十六进制字面量**（有个断言 `expect(panelSource).not.toMatch(/#[0-9a-fA-F]{3,8}\b/)` 守着）。`roleColors.ts` 本身也只返回 CSS 自定义属性名，真实色值仍只写在 `styles.css` 的 `:root`。主区身份条将来（票 22）import 同一个函数，两处不可能漂移。未登记角色走琥珀色兜底，不崩。
- **时间砍掉小时** —— `formatTraceTime` 只取分/秒/毫秒，毫秒补三位。测试直接断言 `12:34.567`，并断言小时位 `09` 不出现。
- **三维筛选不新增字段** —— `kind`/`role`/`uid` 都是 `TraceEntry` 已有字段。有个测试把条目的 key 全列出来断言恰好是 `at/kind/name/role/seq/uid`，多一个字段就红。
- **取消筛选恢复** —— 两个入口：「取消筛选」按钮，以及选中项再点一次。关键断言不是「行数回来了」，而是**筛选态下直接读 `host.store.getEntries()` 断言条目一条没少**（`「取消筛选」按钮把全部条目放回来，且被筛掉的条目一直在 store 里`），这才证明筛选没动 store。还有一条测筛选期间新到的条目：不显示、但已进 store、取消筛选后出现。
- **局部状态** —— 三条测试分别盯采集、盯环形丢弃、盯实例隔离。第二条最关键：`limit: 3` 下先开一个把 event 全筛掉的筛选再继续记，断言留下的仍是最后三条 `a-3/a-4/a-5`——**被筛掉的没有因为不可见就被优先丢弃**。第三条同时挂两个面板共享一个 source，只筛其中一个，另一个不受影响。
- **清空与折叠** —— 清空对每个 source 调 `clear?.()`，`TraceSource.clear` 是**可选**成员（静态快照类来源也该能喂进面板），不支持时点击不抛错。折叠态**由外壳持有**而非面板自己：它要改 `.lab-body` 的栅格（`1fr/400px` → `1fr/40px`），那是外壳的样式。折叠时只留一条竖条 + 条目计数，数据不清。
- **没有截断提示** —— 环形缓冲静默丢弃，`limit: 3` 下记 6 条，断言容器文本不含 `截断|省略|truncat`，且面板源码里没有截断相关的**界面文案**（正则限定在 JSX 字符串字面量范围内，不误伤解释「为什么没有截断提示」的注释）。
- **三列网格** —— `.lab-trace` 是 `grid-template-columns: 16px 62px minmax(0, 1fr)`，测试直接从 `styles.css?raw` 里正则提取该规则块断言数值，并断言每行子元素恰好是 `dot / time / body` 三格。
- **订阅不轮询** —— `useSyncExternalStore`。三条测试：卸载时每个 source 都被退订；开假定时器、一个都不推进而条目已出现（走的是订阅）；面板源码不含 `setInterval`/`setTimeout`。

**接进外壳**：`App.tsx` 的 `TimelinePanelPlaceholder` 已被真面板替换，`LabShell` 持有 `collapsed` 并把 `data-timeline` 写到 `.lab-body` 上驱动栅格切换。trace 来源目前是模块常量空数组 `NO_TRACE_SOURCES`——真实来源是两端客户端的 `toTraceSource(client)`，由票 22 注入。它**必须是模块常量**，每次渲染新建数组会让 `subscribe` 依赖变化而反复重订阅。

**两个踩过的坑**

`useSyncExternalStore` 的 `getSnapshot` 未变化时必须返回**同一引用**。`useMergedTraces` 本来只在「至少有一个 source」时才记忆化，空 source 数组走了 `mergeTraces([])` 每次新建数组的路径，直接 `Maximum update depth exceeded`。改成初始 cache 也参与引用比较后修好——而外壳恰恰就是拿空数组渲染的，这个坑不修就上不了线。

`toTraceSource` 做的是 `getTraces/subscribeTraces/clearTraces` → `getEntries/subscribe/clear` 的改名适配。**不要为此去改 RTM 单文件的方法名**，那是客户要拷走的文件，命名以它为准。

**验证**：`npx vitest run src/shared/timeline/` 63 passed；`npm test` 全量 344 passed / 24 files；`npm run build`（含 `tsc -b`）绿。
