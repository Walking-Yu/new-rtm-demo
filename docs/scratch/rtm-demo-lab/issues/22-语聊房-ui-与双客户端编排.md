# 22 — 语聊房 UI 与双客户端编排

**Blocked by:** 15, 18, 19, 20, 21

**Status:** ready-for-agent

**What to build:** 把前面所有零件装起来，产出可以真实对连的语聊房——一个标签页里两台手机并排（房主视角、听众视角），两个真实客户端，右侧时间线实时串起两端的 RTM 调用与事件。

- [ ] 创建两端客户端，**先连房主再连听众**
- [ ] StrictMode 下重复挂载卸载不泄漏连接（用计数器守卫每个异步步骤）
- [ ] 卸载时两端都断开
- [ ] 渲染耳机告警——两端都会真实播放音频，人工验证时必须戴耳机
- [ ] 渲染生产边界告警，且文案**不含**「已强制执行」这类表述。踢出、封禁、强制麦控都是客户端协作行为，**不构成信任边界**
- [ ] **麦位激活由媒体结果驱动**，这条链路顺序不能改，必须有测试锁住：房主同意申请后麦位先进「加入中」；听众端发布麦克风成功后才转「已激活」；失败则回滚到空位；失败路径下 UI 给出可见反馈
- [ ] 从遗留组件迁移 UI，调整成手机外框内的形态
- [ ] 布局数值照抄 spec，**不要凭感觉调**（用户已两轮确认）：手机高度上限与视口计算式、只有公屏滚动其余区块钉住、底部输入条常驻框内、麦位方框最小高度与头像尺寸、麦位网格列数
- [ ] 手机内区块顺序：状态栏、房间头部、麦位网格、角色专属面板、成员条、公屏、底部操作条
- [ ] 每台手机上方一个身份条：彩色 uid badge 加视角说明，badge 颜色与时间线里的对得上

编排用同一个客户端工厂创建两端，测试注入假工厂。

肉眼验证：两台手机并排、身份条 badge 颜色与时间线 badge 对得上、手机内不裁切、只有公屏滚动、底部输入条在框内、窄屏时时间线转横排。
