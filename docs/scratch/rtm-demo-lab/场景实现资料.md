# 场景实现资料：角色与 RTM 能力标签

来源：遗留注册表 `src/legacy/domain/scenarioCatalog.ts`。

这两组数据**不进新注册表**（新注册表只有 `id`/`title`/`summary`/`status` 四个字段），但按票 01 与票 15 的要求**不丢弃** —— 归档在此，供后续每个场景的 effort 取用。

新场景 id 与遗留 id 的对应见下表「新 id」列；三个带一级分类前缀的遗留 id 已按票 15 的要求改名。

| 新 id | 角色 | RTM 能力 |

| `im-chat` | 发送者、接收者 | 用户消息、消息频道 |
| `voice-room` | 房主、听众 | 消息频道、Storage、Lock |
| `live-pk` | 主播 A、主播 B | 用户消息、消息频道、Storage |

| `room-moderation` | 管理员、房间成员 | 用户消息、消息频道、Storage |

`voice-room` 由遗留的 `voice-room-interaction`（能力：消息频道、Storage）与 `voice-room-seats`（能力：消息频道、Storage、Lock）合并而来，能力取两者并集。

## 说明

能力标签的五个取值来自遗留的 `Capability` 类型：`用户消息`、`消息频道`、`Presence`、`Storage`、`Lock`。它们是遗留实现里各场景动作标注的并集，属**设计意图**而非已验证事实 —— 除 `voice-room` 外，其余场景都还没有真实实现，实际会用到哪些 API 由各自的 effort 定。
