# 19 — 听众端可拷走的 RTM 文件

**Blocked by:** 18

**Status:** ready-for-agent

**What to build:** 房主端 RTM 文件的镜像——听众端的可拷走单文件，导出听众的全部业务动作。多个听众实例都创建同一个类，各自传自己的 uid、各自持有自己的 trace。

**这一票同时是「第二个场景一天产出」的第一次真实压力测试**——如果从房主端复制改造很痛苦，说明模板化不到位，要回头调整。

- [ ] 开工前记录起始时间，真实记录复制改造花了多久，这是验收锚点的实测数据
- [ ] 从房主端文件复制改造：保留连接与分阶段回滚、订阅、消息封装、去重、mutate、trace、重连（约 250 行重复，是刻意的）
- [ ] 语义方法替换为听众的动作：申请上麦、取消申请、接受邀请、拒绝邀请、自己静音、自己下麦，以及公屏消息、表情、礼物
- [ ] 连接、Lock、消息封装、去重、trace、重连几组测试直接复制改 uid 与角色
- [ ] 听众专属行为要测：对自己的静音与下麦**不需要 ack**；收到房主的强制静音与强制下麦命令后要回 ack（这是房主侧 ack 机制的对端，两边要配上）
- [ ] 全绿后检查零依赖
- [ ] 量重复率：若重复超过文件的 60%，**停下来向用户报告**，讨论是否改用代码生成

**不要抽共享的 RTM 基类。** 客户拷一个文件就能跑，比拷两个互相引用的文件有价值。代价是维护时连接与订阅那段要改两处——用「文件骨架模板加编写规程」控制，不用抽象控制。
